Проект состоит из трех сервисов:

- `db` - PostgreSQL
- `api` - FastAPI backend из директории `backend`
- `frontend` - React/Vite frontend, собранный в статические файлы и отданный через nginx

## Назначение системы

Cool Peppers Project - система для загрузки, объединения и анализа бюджетных данных. Приложение помогает работать с данными по лимитам, бюджетным обязательствам, кассовым выплатам, соглашениям, государственным закупкам и платежам.

Основной сценарий системы:

1. Пользователь загружает исходные файлы с бюджетными данными.
2. Backend импортирует данные в PostgreSQL и раскладывает их по предметным таблицам.
3. Пользователь формирует аналитическую выборку по периоду, КЦСР, бюджету, источнику финансирования и минимальной сумме лимита.
4. Система объединяет данные из нескольких источников и возвращает сводный отчет.
5. Результат можно смотреть в интерфейсе, выгружать в Excel или запрашивать через AI-помощника.

## Функционал системы

### Frontend

Frontend реализован на React и Vite. Интерфейс состоит из нескольких рабочих разделов:

- `Обзор` - сводная панель с ключевыми бюджетными показателями, визуализацией исполнения по месяцам, распределением по ведомствам и последними операциями.
- `Конструктор` - основной рабочий экран для формирования выборок. В нем предусмотрены параметры формирования данных, выбор ведомства, метод объединения данных и предварительный просмотр результата.
- `Аналитика` - экран детального анализа бюджетных данных: фильтры по периоду, кварталу и ведомству, показатели динамики, эффективности расходов, отклонений от плана, топ статей расходов и детализация по КБК.
- `Документы` - раздел для работы с отчетами, таблицами и нормативными документами. В интерфейсе есть фильтры по типу документа, статусу, периоду и поиску по названию.

Frontend собирается в статические файлы командой `npm run build` и публикуется через nginx. Для SPA-роутинга nginx настроен так, чтобы отдавать `index.html` при прямом открытии внутренних маршрутов.

### Backend API

Backend реализован на FastAPI и предоставляет API для импорта, аналитики, экспорта и AI-запросов.

Основные endpoints:

- `POST /analytics/batch` - пакетная загрузка исходных файлов. Поддерживаемые поля загрузки: `file_rcb`, `file_agr`, `file_gz_budget_line`, `file_gz_contracts`, `file_gz_payments`, `file_buau`.
- `GET /analytics/report` - формирование аналитического бюджетного отчета.
- `GET /analytics/export-excel` - выгрузка аналитического отчета в Excel.
- `POST /ai/ask` - запрос к AI-помощнику по бюджетной аналитике.

Swagger UI доступен после запуска по адресу:

```text
http://localhost:8000/docs
```

### Импорт данных

Система импортирует несколько типов исходных файлов:

- `РКБ` - данные по исполнению, лимитам, обязательствам и кассовым выплатам.
- `Соглашения` - данные по соглашениям, суммам, получателям и типам документов.
- `Госзакупки: бюджетные строки` - связь закупок с кодами бюджетной классификации.
- `Госзакупки: контракты` - сведения о контрактах, датах, номерах, заказчиках и суммах.
- `Госзакупки: платежи` - сведения о платежных документах и оплаченных суммах.
- `БУАУ` - платежные данные бюджетных и автономных учреждений.

После загрузки данные сохраняются в PostgreSQL и используются в конструкторе аналитического отчета.

### Аналитический отчет

Отчет строится по фильтрам:

- `kcsr_mask` - маска или фрагмент КЦСР.
- `budget_name` - часть наименования бюджета.
- `period_from` - начало периода в формате `YYYY-MM`.
- `period_to` - конец периода в формате `YYYY-MM`.
- `fund_source` - источник финансирования.
- `min_amount` - минимальный лимит ПБС.

Для формирования отчета необходимо указать хотя бы один из параметров: `kcsr_mask` или `budget_name`.

В результате отчет возвращает:

- код и наименование КЦСР;
- бюджет, КФСР и источник финансирования;
- бюджетный период;
- лимит ПБС;
- бюджетные обязательства;
- остаток лимита;
- выплаты РКБ;
- выплаты РКБ по группам КВР 2, 5 и 6;
- выплаты БУАУ;
- суммы соглашений;
- суммы МБТ и субсидий;
- суммы контрактов по госзакупкам;
- оплаченные суммы по госзакупкам;
- детализацию соглашений;
- детализацию контрактов;
- детализацию платежей.

### Экспорт в Excel

Endpoint `GET /analytics/export-excel` использует те же фильтры, что и аналитический отчет, и возвращает файл `.xlsx`. Имя файла формируется автоматически в формате:

```text
budget_report_YYYYMMDD_HHMM.xlsx
```

### AI-помощник

AI-помощник доступен через `POST /ai/ask`. Он специализируется на вопросах по бюджетной аналитике и может вызывать внутренний инструмент формирования бюджетного отчета.

AI-помощник использует:

- историю сессии;
- доступные наименования бюджетов из базы;
- доступные КЦСР из базы;
- параметры периода, бюджета, КЦСР, источника финансирования и минимальной суммы.

По замыслу backend AI-помощник отвечает только на вопросы, связанные с бюджетами, расходами, лимитами и КЦСР.

### База данных и миграции

PostgreSQL хранит данные, импортированные из исходных файлов. Структура таблиц описана SQLAlchemy-моделями в `backend/app/models`.

Миграции находятся в:

```text
backend/app/migrations
```

При запуске Docker-контейнера backend автоматически выполняет:

```bash
alembic upgrade head
```

Это создает и обновляет структуру базы до актуального состояния.

## Требования

- Docker
- Docker Compose v2

## Запуск

Из корня проекта выполните:

```bash
docker compose up --build
```

После старта сервисы будут доступны по адресам:

- Frontend: http://localhost:8080
- Backend API: http://localhost:8000
- Swagger UI: http://localhost:8000/docs
- PostgreSQL: `localhost:5433`

При запуске backend автоматически выполняет миграции:

```bash
alembic upgrade head
```

## Настройки по умолчанию

PostgreSQL в `docker-compose.yml` запускается с такими параметрами:

```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=test1
```

Backend получает эти значения через переменные окружения и подключается к базе по внутреннему Docker DNS имени `db`.
С хоста база опубликована на `localhost:5433`, чтобы не конфликтовать с локальным PostgreSQL на стандартном порту `5432`.

## Полезные команды

Запустить проект в фоне:

```bash
docker compose up --build -d
```

Посмотреть логи всех сервисов:

```bash
docker compose logs -f
```

Посмотреть логи backend:

```bash
docker compose logs -f api
```

Остановить сервисы:

```bash
docker compose down
```

Остановить сервисы и удалить данные PostgreSQL:

```bash
docker compose down -v
```

## Структура Docker-файлов

- `docker-compose.yml` - единый запуск PostgreSQL, API и frontend
- `backend/Dockerfile` - сборка Python/FastAPI backend с `uv`
- `frontend/Dockerfile` - сборка Vite-приложения и публикация через nginx
- `frontend/nginx.conf` - отдача `index.html` для SPA-роутинга и прокси `/api/` на backend

## Переменные окружения backend

Основные переменные задаются в `docker-compose.yml`:

```env
POSTGRES_SERVER=db
POSTGRES_PORT=5432
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=test1
FRONTEND=http://localhost:8080
BACKEND_CORS_ORIGINS=http://localhost:8080,http://127.0.0.1:8080
AI_HOST=host.docker.internal
AI_PORT=11434
```
